# AGENTS.md

## Scope

These instructions apply to the entire repository.

`local-coder` configures OpenCode to use local Ollama models. Prefer small,
reviewable changes that preserve local-only operation, user data, and existing
configuration. Use [`REPO_MAP.md`](REPO_MAP.md) as the starting point when
locating code, and update it when module responsibilities or major flows change.

Do not confuse this contributor file with the OpenCode guidance generated from
`src/opencode/agents.ts`.

## Project conventions

- Use Node.js 20 or newer.
- This is strict TypeScript using ESM and `NodeNext` resolution.
- Include `.js` extensions in relative TypeScript imports.
- Source belongs in `src/`; tests belong in `test/`.
- Use `node:test` and `node:assert/strict` for tests.
- `dist/` is generated by TypeScript and must not be edited or committed.
- Update `package-lock.json` whenever dependencies change.
- Prefer Node built-ins over adding a runtime dependency when practical.

## Change requirements

- Preserve the promise that prompts, source code, hardware details, and
  telemetry remain local unless the user explicitly configures an external
  service.
- Preserve unrelated JSON or JSONC configuration during setup, reinstall, and
  uninstall.
- Never silently discard pre-existing files or user edits, and never remove
  shared or pre-existing models.
- Keep setup preview, application, ownership tracking, reinstall, and uninstall
  behavior consistent.
- Treat paths and repository content as untrusted input. Keep filesystem
  operations inside the intended project or configuration root.
- Execute validation commands as an executable plus argument array. Never
  interpolate repository or user text into a shell command.
- Do not rely only on prompt wording for a guarantee that can be enforced in
  code. Add deterministic validation where practical and document any remaining
  prompt-enforced boundary.
- When generated agent behavior changes, update the relevant prompt tests,
  executable workflow checks, and documentation together.
- Behavioral changes require a focused regression test.

## Validation

Build before running a compiled test directly:

```sh
npm run build
node --test dist/test/<name>.test.js
```

Before completing a code or catalogue change, run:

```sh
npm test
```

For documentation-only changes, verify examples, paths, and links directly.
Run the suite when documentation describes behavior, commands, or invariants
affected by the change.

## Code review rules

Flag changes that could:

- overwrite existing user configuration or edited generated files;
- delete pre-existing or shared Ollama models;
- escape the selected project or configuration directory;
- execute user-controlled text through a shell;
- report success without repository or workflow evidence;
- weaken task-contract, verifier, repair-budget, or workflow-order enforcement;
- replace an executable guarantee with prompt text alone;
- change generated behavior without regression coverage.
